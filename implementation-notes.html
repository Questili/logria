Decisions and tradeoffs

  • Route shape: Using / for the public landing page and /app/* for the authenticated cockpit, matching PLAN.md and preserving docs-domain positioning.
  • Demo-first AI: Merlin uses a deterministic server-side demo operator over typed tools so local OSS quickstart works with no API keys. The tool registry is structured so real model providers can be added without exposing connector secrets.
  • Auth foundation: Server helpers and capability checks are implemented. Demo mode uses a seeded operator instead of requiring external auth configuration. This keeps quickstart under 10 minutes while preserving the permission boundary in the primary codepath.
  • Avalon boundary: Public code will include only generic interfaces and fake data. Avalon-specific mappings/dashboards remain documented as private integration points, not implemented with real customer logic.
  • Prisma 7 change: Prisma no longer accepts datasource URLs inside schema.prisma, so the connection URL now lives in prisma.config.ts with a local default for validation.
  • Test runner tradeoff: The latest Vitest/Rollup native bindings failed macOS code-signing checks in this environment. I replaced it with a deterministic tsx-based test runner to keep focused tests reliable.
  • Next build tradeoff: Next 16 defaulted to Turbopack, but native SWC was rejected by macOS code-signing. The build script uses next build --webpack, which completed successfully through WASM fallback.
