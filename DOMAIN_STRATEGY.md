# Logria Domain and Brand Strategy

**Product:** Logria  
**Primary OSS/docs domain:** `logria.dev`  
**Hosted app domain:** `app.logria.dev`  
**AI assistant:** Merlin  
**Parent company / umbrella:** Questili  
**Initial dogfood product:** Avalon  

## Domain Roles

- `logria.dev` — canonical public home for the open-source project, docs, security posture, connector/plugin guides, and community links.
- `app.logria.dev` — hosted managed version for teams that do not want to self-host.
- `docs.logria.dev` — optional future docs split if documentation outgrows the main site.
- `demo.logria.dev` — optional public demo/sandbox environment.
- `plugins.logria.dev` — optional future plugin directory/registry.
- `status.logria.dev` — optional hosted-service status page.

## Positioning

Logria is the open-source AI operations cockpit for modern SaaS teams.

It connects revenue, support, product analytics, incidents, compliance, and admin workflows into one evidence-linked command center. Teams can self-host Logria or use the managed hosted version at `app.logria.dev`.

## Naming System

- **Logria** — product/platform.
- **Merlin** — AI operator assistant inside Logria.
- **Roundtable** — shared ops review/dashboard module name.
- **Guilds** — plugin/community ecosystem concept.
- **Chronicle** — audit/compliance history module concept.
- **Mandates** — safe admin action/approval concept.

## Brand Boundaries

- Keep Avalon as the first dogfood app and sibling product, not the public name for the ops cockpit.
- Keep Questili as the company/legal umbrella where needed.
- Do not present Logria as making a company compliant by itself; position it as an evidence, audit, and operations control plane.
- Keep `logria.dev` focused on open source and developers; keep `app.logria.dev` focused on hosted workspaces.
